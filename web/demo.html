See it run on one venture.

Kettlewick is a fictional home-care rota venture — one tap when a carer calls in sick, and the cover is found before the kettle boils. Nothing below is a mock-up. Every page is what boss playbook, boss design and boss board --html produce from the records in demo/kettlewick/, which you can read in the repo — the same renderers, the same output an install gives you.

▸the pages
  • The playbook — sixteen chapters over the records: the pitch, the proof, the company; the canvas in three frames; Present as a deck with a VC cut you can trim, and Export PDF.
  • The design space — tokens as swatches with the decision that chose them, contrast computed, the people, the parts, the patterns.
  • The board — every idea and feature by where it stands, read from the records' own status lines.
  • Organization — every record has a home, a shape and one verb that writes it: the filing BOSS does so the founder never has to, grouped by what you're doing, read from the tree after rendering.
  • How it learns — evidence climbing the ladder, a persona getting less made-up, a decision failing its own test, a brand learning real words, a health read becoming the next idea — in the order it happened.

What to look at first: open the playbook, press Present, and step through the VC cut — then open Organization and find the record each slide came from.

▸the rules it keeps

Fictional, and it says so on every page. No real person — no name, no face, no quote. A fictional founder gets no photo, because BOSS never draws a stand-in for a person who has none, and a generated face is a stand-in with better lighting. No real company is a rival.

Generated, never drawn. A demo prettier than what boss produces is a lie the first install exposes. So the demo is rebuilt from the records with the current renderers every time the site is, and a check fails the build when a hole appears on it — a hole on the demo means a feature shipped without demo content, and that is how the demo stays current with the product.
