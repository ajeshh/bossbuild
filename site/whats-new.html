What's new

What's new.

Releases that change something you'd actually do, see or rely on — or that add a practice your project now inherits. Refactors, audits and internal work get no entry, so this list is short on purpose.

Generated from the same file boss sync reads when it tells your project what changed since its pin. In a project, boss status shows your pin against what's installed, and /boss-sync brings you forward as a reviewed diff — never a silent update. The full engineering changelog →

▸releases
  1. v0.300.02026-09-11

    the conscience now fires on Windows without Git Bash. The two hooks BOSS registers moved to Claude Code's exec form — no shell in between — and /boss-sync migrates the old line in existing projects. Needs Claude Code 2.1.139 or newer (claude --version).

  2. v0.299.02026-09-11

    BOSS's list of "what generated design looks like" is current again — it was a 2024 list, and the fix it prescribed had become the 2026 tell. Plus a one-paragraph test that makes sameness visible before you build, and craft floors pre-filled in your style guide so "name the slot" stops withholding facts.

  3. v0.297.02026-09-11

    the conscience now reads your files the same on Windows — CRLF line endings no longer make your loop specs, devlog and frontmatter invisible to it, and its source globs match on \\ paths. A .gitattributes in new projects keeps line endings LF for every cofounder.

  4. v0.296.02026-09-11

    BOSS runs wherever Claude Code runs — the terminal, VS Code, Cursor, JetBrains. It always did; the README and the site now say so. And boss id no longer hands out a duplicate record number on Windows.

  5. v0.295.02026-09-11

    /comp-eval now says what to open, not just what to write — docs before marketing, the changelog, the product itself if there's a free tier — and writes a How they do it entry for the handful of features that touch your bet, which /spec reads as design reference after you've decided to build one.

  6. v0.294.02026-09-11

    The competitive field is finally read by the things that build. /spec opens a rival's where it breaks when you spec something they also have; /landing writes against the alternative people actually use; /pretotype asks "would you switch?" when a real rival is in your evidence; and /comp-eval add tells you whether a new rival is on anyone's shortlist or a phantom — and offers the switch test in the moment when their twist lands on your differentiator.

  7. v0.293.02026-09-10

    The tasks you spot mid-build stop living only in the chat. BOSS notices when the list in the conversation has outrun anything written down, and .claude/rules/feature-context.md — a file that shipped for months with nothing ever writing to it — is now where found work, local decisions and open questions actually go.

  8. v0.292.02026-09-10

    The website and the generated docs catch up with the design work — the design page now explains the eight layers a design system actually has, and why one that can only add rules locks your design in.

  9. v0.291.02026-09-10

    Four small seams, each cheap now and expensive later — strings in one place, one word per concept in your props too, how waiting should feel, and a "wrong if" line on every design principle.

  10. v0.290.02026-09-10

    The parts of a product nobody designs now get asked about. Your pattern set can seed the three element families that get decided by accident — inputs, data display, icons — and /ux-check asks once what else a user sees: the receipt email, the settings screen, the 404.

  11. v0.289.02026-09-10

    boss craft accessibility is new — the guidelines BOSS reasons from, so designer can tell you which principle something violates and where to look it up, instead of reciting four rules. Plus contrast-guard: the one accessibility property that is arithmetic, computed over the token pairs you declared.

  12. v0.288.02026-09-10

    You get a brand doc that grows instead of one nobody wrote. docs/BRAND.md — who it's for, what it promises, what it refuses, how it sounds — is seeded by whichever skill needs it first, starts nascent, and gains rows from what real people actually said. It is not a design file: the landing page, the fake door, the pitch and the design tokens all read the same one.

make it real.
$npm install -g oyeboss
$brew install ajeshh/boss/oyeboss

Either puts boss on your PATH. Needs Node 18+ and Claude Code — in the terminal, VS Code, Cursor or JetBrains, on macOS, Linux or Windows; BOSS runs wherever Claude Code does.

Source on GitHub · npm · MIT licensed · zero dependencies · no account.

Built by Ajesh Shah in Oakland, California. About → · LinkedIn · GitHub

Every byte stays on your machine. The only network call BOSS makes is when you type boss update — a GET to the public npm registry asking for a version number. Nothing is sent about you, your code, or your ideas. No analytics, no telemetry, no phone-home; the check never runs unless you ask for it. It’s ~30 lines in src/update.js and you can read them.

Where this actually is: v0.300.0, built in the open and used daily by its author. Very few other people have used it yet. BOSS is its own first project — it runs its own modes, files its own ideas, and its conscience nudges the person building it. If that sounds like a reason to wait, that’s a fair read.
