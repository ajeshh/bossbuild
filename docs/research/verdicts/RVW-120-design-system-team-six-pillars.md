# RVW-120 — a design system is an operating model: six pillars with owners

## The claim
- **Source:** a lead product designer for design systems at a large listings company.
- **Core assertion:** a design system defined by its deliverables buckles under adoption. Run it on
  six owned pillars (core systems, components, design tooling, education and communication,
  research and documentation, culture), each mapped to a business outcome. For a team of one, the
  pillars become a prioritization guide.
- **Inbox file:** `~/Projects/inbox/bossbuild/The 6 pillars…pdf`

## Rubric
| # | Question | Finding |
|---|---|---|
| 1 | Contradicts a PRINCIPLE? | **#2.** Six named functions with owners is an org chart; even the "team of one" reading hands a solo founder six things to hold. |
| 2 | Evidence grade | Practitioner framework, no data. |
| 3 | Duplicate or sharpen? | Where it touches BOSS, BOSS already has the mechanism: core systems → tokens, components → index + usage pages, research → EVID-grounded principles, documentation → `boss design`. Culture and education have no founder-scale reader. |
| 4 | Who serves / harms? | Serves in-house design-system teams. Harms a solo founder by making the system look like a department. |
| 5 | Cost / ceremony | Much heavier. |

## Verdict: REJECT
An org model for a team that exists. A founder's design system is a file the agent reads, not a
function someone staffs, and BOSS has said so since IDEA-091.

## If REJECT / NOT-YET
- **Why not:** PRINCIPLE #2. Ceremony with no founder-scale reader.
