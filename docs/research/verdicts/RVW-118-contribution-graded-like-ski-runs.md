# RVW-118 — design-system contribution, graded by size and skill like ski runs

## The claim
- **Source:** a design-system lead with a decade across banks, telcos and a government system.
- **Core assertion:** contribution doesn't speed a design system up. It slows it down, and the
  benefit is bringing outside knowledge in. There is no single process: tailor it by who is
  contributing, whether it's worth it, and its category (groundwork → bug fix → content → asset →
  component feature → component → multi-disciplinary pattern → service). Start contributors on
  the green runs.
- **Inbox file:** `~/Projects/inbox/bossbuild/Mount Contribution…pdf`

## Rubric
| # | Question | Finding |
|---|---|---|
| 1 | Contradicts a PRINCIPLE? | Fails #2 at BOSS's cohort: a contribution model needs contributors. |
| 2 | Evidence grade | Experienced practitioner, framework from experience, no data. |
| 3 | Duplicate or sharpen? | BOSS has the founder-scale front door already. *A usage page with `status: proposed` is a request*: anyone can ask for a part, say what it's for and why it's new, and the next `/design-review` picks it up. The size-grading is new to BOSS but has no reader. |
| 4 | Who serves / harms? | Serves multi-team orgs. |
| 5 | Cost / ceremony | Heavier. |

## Verdict: NOT-YET
Sound, and the "contribution costs more than it saves, and that's fine" honesty is worth remembering.
There is no one in a founder's project to grade.

## If REJECT / NOT-YET
- **Re-open condition:** the same trigger as RVW-116. A second person contributes UI to a BOSS
  project and the `proposed` usage page proves too coarse (a bug fix and a new component getting
  the same treatment).
