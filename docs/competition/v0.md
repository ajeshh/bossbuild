# v0 — Vercel

> **In their words** (v0.app, checked 2026-09-11): *"v0 is an AI agent that helps anyone create real
> code and full-stack apps and agents."* — *"Ship features, refine designs, update copy, and create
> live prototypes, all with a prompt."* Renamed from v0.dev to v0.app January 2026; "the new v0"
> shipped 2026-02-03 (sandbox runtime, branch-per-chat, PRs, DB integrations, token billing).

## What it is

A prompt-to-running-app builder **that owns the runtime.** Describe → v0 generates (Next.js,
Tailwind, shadcn/ui) → live preview in a sandbox → one-click deploy to Vercel → a URL. Git is a
first-class panel: a branch per chat, PRs against main, deploy on merge. Database integrations
(Snowflake, AWS, Supabase-class), MCP tools, Figma inspection, an in-browser terminal since May 2026.
Four in-house models (Mini / Pro / Max / Max Fast) plus a picker for GPT-5.6 Sol and Claude Opus 5.

**The twist, against BOSS's bet:** v0 is the *build engine*. BOSS has none — BOSS is guidance
wrapped around a host (Claude Code) that does the building. They are not the same job. **Where they
overlap is exactly one place:** both try to keep an AI builder on rails, and v0's answer to that is
worth reading closely (§ How they do it).

## Why they might win

- **They own the runtime, and nothing in BOSS competes with that.** A founder who wants a thing on
  the internet *today* gets prompt → running app → deployed URL inside an hour, with Vercel's
  infrastructure underneath. BOSS's `/ship` is a pre-flight checklist over someone else's deploy.
- **Their design-system feature is the retrieval-shaped thing BOSS's design program argued for,
  shipped as product** — an adapter to real sources, verified by building a starter app, grounded
  so *"if a component, prop, or token cannot be verified from the sources, v0 should not use it."*
  (Guidance, not enforcement — see below — but it is the right shape.)
- **Velocity.** 2–3 major changelog entries a month across the last six, plus near-daily fixes.
  Agentic workflows, MCP, terminal, Figma inspection all landed inside one quarter.
- **Distribution.** It is Vercel's front door for AI building; every Next.js developer already has
  an account.

## Where they're weak

- **No "why" layer at all.** A Project holds deployment, domains, env vars, integrations — *"the
  documentation provides no evidence that Projects maintain persistent memory, knowledge, or
  context beyond their configuration settings."* The memory is the git history. Nothing records a
  decision, an assumption, or what the founder was trying to learn. **This is the whole of BOSS's
  differentiator and v0 has none of it, and none of it on the roadmap.**
- **Instructions are opt-in per chat and static.** See § How they do it. Nothing in v0 reads what
  the founder is doing and speaks up.
- **Credit burn is the #1 complaint by volume** (six of the twenty most recent community topics are
  billing; *"$30 USD on a single prompt"*). Retries on the model's own mistakes cost the user.
- **Project degradation past ~30 prompts** and *"not listening to prompts"* — the long-session
  failure BOSS's whole session-interior program (IDEA-094) is about, showing up in their forum.
- **Stack lock-in.** Next.js / Vercel or nothing. *"i asked it for some basic svelte code. it spat
  out react."*

## How they do it — the three features that touch BOSS's bet

### 1. Keeping the AI on rails · **Instructions** + **Design Systems 2.0**

**Instructions** (v0.app/docs/instructions, opened 2026-09-11):
- **Scope:** account-level. *"Your instruction is now saved to your account and available across
  all your chats and projects."*
- **Activation: per chat, opt-in.** *"Click the + button in the prompt bar → check the instructions
  you want to apply."* Multiple can be on at once. **Not always-on.**
- **Two presets:** *"Be Concise"* and **"Plan Mode"** — *"v0 creates detailed plans before code
  changes and requests approval."*
- **Mechanism: static text injected into the prompt.** No mention of anything that reads the
  project or the user's behaviour and adjusts.

**Design Systems 2.0** (v0.app/docs/design-systems-2, opened 2026-09-11):
- *"A skill is a small, focused set of instructions v0 keeps with your work and pulls in when
  relevant."* *"Not a copy of your docs; it is an adapter that tells v0 where your source lives,
  which components, props, and tokens are safe to use."*
- **Sources:** an npm package / `.tgz` / repo, Storybook or docs, Figma frames, a consuming app.
  Up to three reference sources in `v0.json`.
- **Ask vs automatic:** the user provides sources; v0 *"reads them and builds a starter app to
  verify it understands your system"*, then *"pauses for your review before saving anything."*
- **Grounding rule:** *"If a component, prop, or token cannot be verified from the sources, v0
  should not use it."* — **guidance to the model, not a check on the output.** No documented
  behaviour for a needed component that isn't in the system, and no stated criteria for *"when
  relevant."*

**What their users expect** (4–5★ read, per the rule): *"it just knows my design system after
import"* — the expectation is that grounding happens without the user re-stating it every chat.

**Against BOSS:** BOSS's `CLAUDE.md` is always-on where v0's Instructions are opt-in per chat; BOSS's
conscience hook **reads project state** and speaks on a predicate, which v0 has no equivalent for;
BOSS's `design-tokens-guard` is a **boundary** (a hook that checks the edit) where v0's grounding
rule is a **filter** (a sentence asking the model to comply). v0's *Plan Mode* preset is the closest
thing to `/spec` — a plan before code, with approval — and it is one checkbox, not a record.

### 2. Where you are, and why · **Projects** + **branch-per-chat** + **Work Details**

- A Project shares *"deployment, hosting, domains, and environment variables for the chats
  connected to it."* That is the whole of what it holds.
- **The unit of work is a chat**, and since 2026-02 *"a new Git panel lets you create a new branch
  for each chat, open PRs against main, and deploy on merge."* User creates the branch and opens the
  PR; deploy is automatic on merge.
- **Work Details** (Oct 2025) shows *time, files modified, LOC changed* per generation.
- **Linear and Glean MCP integrations** for issue and doc context — i.e. the task list lives in
  Linear, not in v0.

**Against BOSS:** v0 answers *"what changed"* (git) and *"how much"* (Work Details) and never
*"why"* or *"what were we trying to learn."* There is no idea, no spec, no decision, no evidence
record — and the forum's *"30+ prompts gets the project broken"* is the cost of that showing up in
their users' words. BOSS's board, records and `feature-context.md` have no counterpart here.

### 3. Getting it on the internet · **one-click deploy** + **sandbox** + **PR flow**

- Prompt → sandbox preview (50% faster since 2026-05) → *"Deploy to production immediately, or
  open a pull request for review."* Unified GitHub publish flow with preview deployments (2026-09-01).
- Database and AI Gateway integrations are zero-config inside a Project.

**Against BOSS:** this is where they win outright and BOSS should not pretend otherwise. `/ship`
detects a stack and runs a pre-flight; v0 *is* the deploy. A founder on BOSS reaches a URL through
whatever host they chose; a founder on v0 reaches it through the same button that built it.
